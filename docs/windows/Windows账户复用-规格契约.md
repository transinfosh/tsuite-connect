# Windows 账户复用规格契约

## 已确认设计

新 Windows 接入默认使用实际执行受控端命令的 Windows 管理员身份；以提升权限后的进程身份为准。每个会话仍有独立的授权密钥、SSH 监听、隧道、任务和期限，不创建新账户。

- 支持本地及 AD 管理员；拒绝 SYSTEM、服务身份、Entra ID 身份和 TSuite 临时账户。不支持时明确失败，不自动创建替代账户。
- 本机会话记录 `account_mode=existing`、规范账户名、不可变 SID 和 SSH 登录名。登录名通过已认证 enrollment 绑定到完整会话，支持端使用该绑定连接。
- 本地 SSH 使用本地 SAM 名；AD 使用 `GetUserNameEx(NameUserPrincipal)` 获得的 UPN 并验证其 SID，服务端 AllowUsers 使用小写规范 SAM 名。现代 Unix SSH 拒绝域反斜杠登录名；不支持的本地名字直接拒绝。
- 不读取用户密码，不修改密码、组成员资格、账户启用状态或账户有效期；不写用户的共享 SSH 授权文件，不删除或卸载其用户配置。
- 续期仅更新本会话授权文件和本地期限。关闭/过期仅撤销本会话密钥、监听、隧道、任务和受控进程树，不按用户名终止进程。
- 监听进程及其子进程进入独立 Windows Job，控制进程退出或任务停止后自动终止受控子进程。账号原有桌面、其他会话和业务程序不属于该 Job。
- 账户更名、SID 不匹配和不支持的 SSH 用户名明确报错，不能换绑另一身份续期。

## 边界和兼容

`customer_ssh_user` 是 Windows enrollment、持久会话、公开会话元数据和 enrollment 响应的可选字段。同一 nonce/Host Key 重试还须保持账户绑定一致。Linux 不接受该字段。

新 bootstrap 与新支持端、broker、Edge 管理器需要配套发布；先部署读取可选字段的各端，再启用新 bootstrap。未提供该字段的旧会话继续使用原临时账户名。

旧本地状态缺少 `account_mode` 时按 `temporary` 处理，继续原有所有权检查和账户/配置回收。未知模式或身份字段不完整时失败，不降级为临时账户清理。待清理的旧会话不转换身份；升级不重启 Windows。

原 Windows 支持范围、租约和关闭协议不变。新 Windows 会话不再用账户过期作为撤销手段，仍由独立授权原生到期、监听/隧道期限和受控进程生命周期约束访问。管理员通过 SCM 等机制明确安装的持久业务服务不属于 SSH 子进程清理对象。

## 验证边界

必须验证正常接入、重复登记、续期、关闭、过期、安装回滚、并发会话、异常停止及旧状态兼容。Windows Job 和现有账户身份认证须通过真实 Windows CI；域环境与客户生产账户不得仅凭单元替身标为已验证。
