# Connect 控制台规格契约

## 范围与模块边界

本功能负责网页登录、远程会话管理、命令展示及本地用户管理。React + TypeScript 客户端（采用 shadcn/ui 组件）由
`frontend/` 构建，Python 标准库 WSGI 入口由 `console/tsuite_connect_web.py` 提供；
旧控制台处理器保留 OAuth、客户端下载、领取协议及兼容表单入口。

浏览器默认使用单页面导航，直接打开 `/connect/users` 或 `/connect/session/<id>`
也返回同一入口，再经 JSON API 获取授权后的数据。旧 HTML 表单仍执行 CSRF 校验。

## 界面改版约定

用户已确认采用 React + shadcn/ui 替换此前 Vue 与手写组件的实现。
采用官方默认 Neutral 主题及语义颜色，以清楚的状态文字为主，移除英文装饰标题、
独立统计卡片和固定侧栏；保留客户分组、搜索、统计摘要及完整会话/用户操作。
弹窗、输入、按钮、状态、Card、Tabs、Table 和导航统一使用官方 shadcn/ui 组件，图标采用 Lucide。
整页布局采用标准 Tailwind 间距和响应式工具类，不额外定义布局选择器或业务配色。
桌面使用简单顶栏与紧凑列表，手机保留清楚的逐项操作。提供键盘焦点、减少动画支持，
不以颜色单独表达状态。受控弹窗记住触发按钮，关闭后归还焦点；忙碌时禁止取消。

点击导航立即切换路由和页面框架，再异步读取目标数据；不得等待网络响应后才切换。
当前登录内存中已有列表时立即显示，并在后台刷新；首次加载使用组件骨架和加载指示。
详情刷新保留已显示内容，切换到其他详情不得显示前一个会话的数据。读请求不占用变更操作锁，
等待时仍可导航；过时路由或旧身份的响应不得覆盖当前页面或显示无关错误。退出清理内存数据。
支持 View Transitions 的浏览器对内容切换与筛选使用 120–160ms 过渡；弹窗与菜单沿用组件动画。
不支持该 API 时正常切换，系统减少动画偏好下关闭过渡。紧凑布局不缩小必要的操作控件。

本次只替换前端与构建依赖，不修改后端认证、接口、SSH 协议或数据库。为适配 Radix 动态样式，HTML 每次响应生成
独立的样式 CSP nonce，组件通过 get-nonce 读取；仍拒绝任意内联脚本与样式。
验证计划为 TypeScript、生产构建、既有 Python 契约测试、Chromium 全流程及手机布局。
当前新实现验证结果以测试映射为准。

## 已确认设计与实现

### 登录与授权

- 网页登录默认固定有效 7 天，不因轮询或操作无限续期。配置项 `session_ttl_seconds`
  接受 8 小时至 30 天的整数秒数；数据库期限与 Cookie Max-Age 一致。
- GitHub 与本地密码加 TOTP 使用相同网页有效期。OAuth state 10 分钟、TOTP challenge
  5 分钟及最多 5 次尝试、邀请 30 分钟及单次使用沿用原规则。
- Cookie 保留 Secure、HttpOnly、SameSite=Lax。本地 challenge 保留独立路径和 SameSite=Strict。
- 退出删除服务端会话；禁用本地用户、完成 TOTP 重绑撤销其现有网页会话。
- GitHub 在登录时检查配置的组织及可选团队，未加入、邀请未接受、read:org 或组织 OAuth
  批准缺失时明确说明要求。403/404 不能可靠区分上述原因，界面不得伪称已确认具体一个原因。
- GitHub 成员资格在现有网页登录期内不重新检查；移除组织成员不会立即撤销已发出的网页会话。
  管理员须结合权限敏感度设置期限，紧急撤销需删除该账号的服务端网页会话。当前没有提供
  GitHub 会话管理页面，也不持久保存 GitHub access token。
- 7 天是网页身份期限。客户接入授权的默认 15 分钟领取窗口、SSH 闲置租约与清理机制不随之延长。

### 会话与一次性授权

- 列表按客户环境分组，只显示 issued/enrolled/revoking，提供搜索、刷新、详情及关闭。
  可见页面每 15 秒刷新列表；轮询不续租 SSH 会话。
- 新建默认 Linux，支持用途可空，客户环境标识和长度限制与 broker 一致。
- 命令页只有两步：受控机（客户服务器）和控制机（发起远程操作的本机）。AI 操作说明
  位于控制机步骤内，不单独编号。界面称谓不改变 `platform`（受控机）与 `operator_platform`（控制机）字段。
- 受控机系统在接入前可切换；控制机系统只改变控制机命令及 AI 说明。两端拥有独立待处理状态，
  切换一端不禁用另一端选择。同端等待期间禁止重复提交；两端都选择时，基于上一条确认响应
  依次提交，避免旧平台覆盖新平台。失败立即停止后续选择，不自动重试，明确告知未提交的选择。
- 更新期间只暂停对应命令的复制；AI 说明依赖两端，任一端更新时暂停 AI 复制并显示进度。
  受控机接入后仍锁定其系统，控制机选择不受该锁定影响。
- 客户命令、支持机授权与 AI 说明仅存在当前页面内存；不放入 URL、localStorage、
  sessionStorage 或后台详情。所有 HTML、API、资源和下载响应禁止缓存。
- 刷新命令页面或离开后通过详情进入，不重新显示已发出的授权。兼容旧会话仅有客户命令时，
  不显示不可用的操作端系统选择。
- 关闭必须确认，提交期间禁止重复操作并显示等待状态。只有客户清理确认后才撤销连接；
  未确认时保留重试入口，不自动 force-close。SSH 在已返回 cleanup-scheduled 标记后以
  255 退出仍视为清理已调度，这是已有 broker 行为，本次补充浏览器边界和回归保障。

### 本地用户

管理员可创建邀请、启用/禁用用户、创建 TOTP 重绑链接；操作员不得调用这些接口。
邀请设置密码后绑定验证器，支持二维码、手动密钥和 otpauth 链接；完成后返回登录。
当前用户不能在页面禁用自己。邀请、重绑链接为临时凭据，只在生成页面展示。

### 错误与可观测性

JSON 错误格式：`{"error":{"code":"...","message":"可读原因与处理建议","request_id":"诊断编号"}}`。
登录过期使用 401，权限/CSRF 使用 403，远程状态冲突 409，broker 故障 502，操作超时 504。

GitHub 组织/团队要求、客户清理未确认、隧道不可达、SSH 认证及主机密钥失败分开说明；
受控机安装因旧活动会话冲突被拒绝时，终端显示旧连接 ID、客户环境名称及“远程会话”查找关闭指引。
只改善定位信息，不覆盖或自动关闭活动连接，不消费新会话授权。
未知故障显示退出码和诊断编号。诊断编号与服务端日志一致。原始 stderr、请求正文、密码、
OAuth token、一次性授权与私钥不输出到页面或普通日志。日志仅包含编号、操作类别、错误类别
及退出码。仅有编号不能替代线上故障证据；不得据此宣称已修复所有关闭连接失败。

网络断开/等待超时不能证明操作未执行。界面明确提示刷新状态确认，不自动重发创建或关闭。

## 构建与安装

构建需要 Node.js 22.12+，运行仍为 Python 标准库与既有系统依赖，无需运行 Node 服务或访问 CDN。
锁定版本见 `frontend/package-lock.json`。先执行 `npm ci --prefix frontend`、
`npm run build --prefix frontend`。安装器在修改系统前确认构建入口存在，复制 Python Web
适配器和 `console/static`；升级保留自定义登录期限。CI 执行构建、API 单测及 Chromium 回归。

源码归档不包含被忽略的构建产物，部署前在维护机或 CI 构建后随目录一起传输。

## 兼容影响

- 新增 `/connect/api/*` JSON 接口和 `/connect/assets/*` 静态资源，同一 `/connect/*` 反向代理即可覆盖。
- 原 GitHub 登录/回调、本地 challenge Cookie 路径、operator-client 下载和 operator-claim 地址不变。
- 不修改 SSH 协议、客户脚本、operator 脚本、堡垒机会话状态、密钥或 sudo 权限。
- 原 SQLite 结构不变；既有网页会话保留原到期时间，重新登录后采用新期限。
- Python 入口必须与新增 Web 模块、已构建的静态资源同步安装，单独替换旧 Python 文件不足以升级。
- 前端改版的隔离验证不等同于线上验收。发布部署结果另见 `docs/validation/` 对应记录；
  真实 GitHub OAuth 和客户关闭行为仍须按记录中的验证边界判断。

验证情况见[测试映射](控制台-测试映射.md)，预期行为见[BDD 场景](控制台-BDD场景.md)。
